# ニュースの公開手順

ニュースは Nuxt Content で管理します。初期状態では記事を掲載しません。
`content-demo/` は架空の記事を使った開発用資料です。公開用の告知として使用しないでください。

## 外部コンテンツの配置

既存の外部コンテンツは `public/_content/articles/` に配置します。
外部コンテンツのディレクトリを `public/_content` へリンクする方式も使用できます。
ビルドは外部コンテンツを上書きせず、配置先がない場合は空のディレクトリを作ります。

以前のビルドが作成した `content-demo` へのリンクが残っている場合、ビルドは停止します。
リンク先を確認してリンクだけを外し、公開用コンテンツを配置してください。
`content-demo/` 自体は削除せず保存します。

`public/` 内のファイルは、その URL から直接取得できます。
また、Nuxt Content のコレクションはクライアントに配信されます。
公開条件は画面の掲載制御であり、非公開情報を保護する仕組みではありません。
下書き、未確認の告知、公開前の機密情報は `public/` やこのコレクションに配置しないでください。
公開する画像などの添付ファイルも、権利と内容を確認してから配置します。

## 掲載条件

公開担当者が次の内容を確認した記事だけを配置してください。

1. 告知の本文、実際の提供状況、告知日時が一致している
2. 掲載対象が Clasteria です
3. リンク先と画像が一般公開できる
4. 公開用のメタデータに `publicationStatus: published` と `brand: clasteria` を明記している

記事の先頭には、次のようにメタデータを記述します。これは形式の例であり、実際の告知ではありません。

```yaml
---
slug: 20261001-example
title: 確認済み告知のタイトル
author: Clasteria
publishedAt: 2026-10-01T12:00:00+09:00
publicationStatus: published
brand: clasteria
tags: []
---
```

`publicationStatus` を省略した記事は `draft`、`brand` を省略した記事は `unconfirmed` として扱います。
以前から配置されている記事も、確認後にこの 2 項目を指定するまで掲載しません。
`draft`、他ブランド、未確認ブランド、未来の `publishedAt` は、一覧、件数、記事 URL のすべてで除外します。
Pixelsia と Connectia の告知を同じニュース面に掲載する運用は、今回の公開範囲には含めません。

`publishedAt` は、イベントの開催日ではなく告知の公開日時です。タイムゾーンを明記してください。
静的サイトではビルド時点の掲載状態を配信するため、掲載内容や公開日時の変更後は再ビルドと再配信が必要です。
未来の日時に自動で公開される予約配信機能はありません。

一覧は 1 ページに 20 件表示します。静的 HTML の生成対象は同じ公開条件で全件登録するため、
2 ページ目以降の記事 URL も直接開けます。

## 確認

- `pnpm exec vitest run app/composables/articles.test.ts scripts/prebuild-content.test.ts` で公開条件を確認します
- `pnpm generate` 後、ニュース一覧、件数、公開記事の本文と日時、一覧へ戻る操作を確認します
- 未登録、未確認、他ブランド、公開前の記事 URL が 404 になることを確認します
- 記事がない場合は「現在、公開中のお知らせはありません」と表示されることを確認します
