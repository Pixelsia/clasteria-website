# ページビジュアルエディター

既存ページの Vue コンポーネントを GrapesJS OSS core で編集します。新しいアカウントや外部 CMS は不要です。

## 開く

- ブランチプレビューで Home 右下の「Home を編集」を選ぶか、`/editor` を開きます。既存の Cloudflare Access の認証が適用されます。
- `pnpm dev` でも利用できます。静的生成をローカルで試す場合は `NUXT_VISUAL_EDITOR=true pnpm generate` を実行します。
- Cloudflare Pages の `main` ブランチではエディターを生成しません。通常の本番ビルドでも明示的に有効化しない限り生成しません。エディターの URL は検索対象から除外します。

## 編集できる内容

上部のページ選択で編集先を切り替えます。公開済みか非公開かを画面に表示します。

- Home: メインビジュアル、紹介、ニュース、お問い合わせ
- お問い合わせ: メインビジュアル、メール・Discord の説明、事前案内、FAQ
- ニュース一覧: メインビジュアル、記事がないときの表示、案内。掲載記事は従来の Clasteria 公開条件で取得します
- 参加・アクセス: 仮アドレス、接続情報、参加前の案内。未確定の版・バージョン・ポート・参加時期は準備中と表示します
- 非公開の鬼ごっこ・かくれんぼ: メインビジュアル、遊び方、ルール、紹介カード、案内
- 非公開のログイン・購入登録・リーダーボード: 説明や表示枠。ログイン、登録、決済、ランキング集計の機能は追加しません
- 非公開の CodingCraft 紹介: 文章と画像。実際のサービスは既存の外部リンクから利用します
- 新しい記事の下書き: Clasteria の記事 1 件の情報、見出し、本文を別に準備します。JSON と Markdown に書き出せます

ページごとに対応するセクションだけを追加・複製・削除できます。最大 12 セクションです。メインビジュアル、記事の情報は各 1 個を維持します。
キャンバスやレイヤーで並べ替えられます。「上へ」「下へ」でも操作できます。
中央の実画面では、緑の点線で示される文章をダブルクリックして直接編集できます。Enter で改行、⌘Enter または Ctrl+Enter で確定、Esc で編集開始前の文章に戻します。文章はプレーンテキストとして扱います。同じ文章が複数の項目にある場合や空欄は、右側の項目で編集してください。

文章、登録済みの画像・リンク・アイコン、アクセント色、背景色、上下の余白を変更できます。
見出し・説明文・カード・FAQ などの文章欄では、Enter キーで改行できます。キャンバス、プレビュー、下書きの保存・読み込みでも改行を保持します。ボタンの文字や URL などは 1 行の項目です。
Home と各ページのメインビジュアルは、「ネザーゲートのある広場」を初期画像として使用します。画像と背景の重ね方も、Home と同じ明るさにそろえています。保存済みの下書きや本文中の画像は変更しません。以前の下書きには保存時の画像が残るため、変更する場合は背景画像から選び直してください。
お問い合わせ先、記事の対象ブランドと下書き状態は安全のため固定です。

「ボタンの色」はアクセント色と独立して変更できます。既定は編集画面と同じ深い緑（`#26715b`）です。旧 v1 下書きも読み込め、保存済みの文章・画像・アクセント色を維持します。Home の旧下書きには仮アドレスと参加案内リンクを補います。仮アドレスは接続リンクや稼働中の表示ではありません。

参加・アクセスページも PC 書き出し、ページ別の自動保存、Undo/Redo、プレビューの対象です。任意のサーバーバックアップは追加テーブルを使い、既存下書きのテーブルや行を変更しません。GET はテーブルを作りません。
「元に戻す」「やり直す」、PC・スマートフォン幅での表示確認もできます。履歴はページを切り替えるとリセットします。

ニュース一覧のデザインと記事本文は別の下書きです。現在の公開用記事フォルダーには記事がないため、既存記事を選んで編集する画面は設けていません。
新しい記事は `publicationStatus: draft`、`brand: clasteria` で書き出します。本文は安全な見出しとプレーンテキストで構成し、任意の HTML や埋め込みを扱いません。
公開用フォルダーへ自動配置する機能や予約配信はありません。記事の確認・配置は `content/README.md` を参照してください。
ヘッダーとフッターは共通部品のため、このエディターでは編集しません。

## 保存とプレビュー

基本はローカルで編集します。ブラウザーへの自動保存と、PC の JSON ファイルへの保存は別です。「この PC に保存」は JSON のダウンロードを開始します。ダウンロードが完了したファイルを保存先で確認してください。既存のファイルを自動で上書きしません。読み込みで元に戻せるため、節目のファイルを保管してください。ダウンロード後も編集すると、現在の内容がファイルに未書き出しであることを表示します。

ツールバーの「その他の保存」を開き、「サーバーにバックアップ」を押すと、Cloudflare D1 に保存します。同じ Pixelsia アカウントで同じブランチの編集画面を開けば、別の PC から読み込めます。サーバー保存は公開操作ではありません。公開ページは下書きを読み込みません。

編集画面の上部にある保存の案内は、右上の「×」で閉じられます。ツールバーの「保存の案内を表示」で再表示できます。新しく画面を開くと案内は閉じた状態です。ブラウザー保存と PC ファイルの書き出し状態は、常にツールバー下に表示します。閉じても保存・読み込みボタンと保存状態は残り、エラーや確認画面も表示します。

下書き、サーバーのリビジョン、復旧用バックアップ、プレビューはページごとに分離します。Home の以前の JSON、端末バックアップ、サーバーの下書きもそのまま利用できます。

編集内容は端末・ブラウザーにも自動バックアップします。サーバーへの未保存表示と、端末のバックアップ表示は別です。保存先が未設定の場合や通信・認証に失敗した場合は、その旨を表示します。サーバー保存に成功したとは表示しません。

初めての端末ではサーバーの下書きを読み込みます。端末の下書きがある場合は勝手に置き換えません。「サーバーの下書きを読み込む」で確認してから読み込めます。別の端末で更新されていた場合は保存を拒否します。必要な変更を JSON に書き出してから最新版を読み込み、変更を反映してください。

「この PC に保存」で JSON を保管してください。別の端末や別のプレビュー URL では「PC のファイルを読み込む」で復元できます。読み込みは現在の下書きと編集履歴を置き換えるため、必要な変更は先に書き出してください。「初期デザインにリセット」は確認してから実行します。

読み取れない端末の下書きは、自動で上書きせずに保護します。「元のバックアップを書き出す」で元データを保管できます。復旧用保存枠が使用済みの場合や容量不足の場合は端末への上書きを止めます。その場合は、元データと現在の下書きを両方書き出してください。

ページ切り替え時にサーバー未保存の内容がある場合は確認します。端末への保管に失敗した場合や通信中は切り替えません。別のページの JSON やサーバー応答は拒否します。

「プレビュー」は選択中のページを同じ Vue コンポーネントと公開済み記事を使用します。移動先は実際のサイトなので、リンクを開くと公開版に移ります。プレビューの表示だけで公開はされません。機密情報は入力しないでください。共有端末では下書きが残ります。

## サーバー保存の設定

設定は Cloudflare の既存 Pages プロジェクトの Preview 環境だけに適用します。新しい資格情報や公開用 CMS は不要です。本番環境にデータベースをバインドしないでください。

1. 承認後に、専用 D1 データベース `clasteria-editor-drafts-preview` を作成します。有料プランへ変更しません。
2. そのデータベースに `migrations/0001_editor_drafts.sql` と `migrations/0002_multi_page_editor_drafts.sql` を適用します。既存の Home 環境には 0002 だけを追加します。0002 は Home 用の `editor_drafts` を変更せず、新しい `editor_page_drafts` テーブルを 1 文で作成します。既存データの削除・移動はありません。0002 を未適用の場合も、認証済みユーザーが最初に有効な非 Home ページを保存すると、同じ固定スキーマを自動作成します。GET は作成しません。認証・プレビュー用ブランチ・送信元・文書の検証に失敗したリクエストは作成も保存もしません。
3. Pages の Preview 環境に D1 バインディング `CLASTERIA_DRAFTS` を追加します。
4. Preview のランタイム変数に、次の値を設定します。
   - `CLASTERIA_ACCESS_ISSUER`: 既存 Access チームの `https://<team>.cloudflareaccess.com`。末尾のスラッシュは付けません。
   - `CLASTERIA_ACCESS_AUD`: 既存プレビュー用 Access アプリケーションの Audience (AUD) Tag。
   - `CLASTERIA_EDITOR_ALLOWED_EMAILS`: 保存・読み込みを許可するメールアドレスのカンマ区切り一覧。初期設定は承認された本人のアカウントだけです。
5. 同じブランチを再デプロイし、認証済みの独立した 2 セッションで保存・読み込みを確認します。

これらの値はサーバーだけで読み取ります。Nuxt の公開ランタイム設定やリポジトリーにトークン・秘密情報を置かないでください。Access の既存ポリシーを緩める必要はありません。Access アプリケーションが編集画面と `/api/editor/*` の両方を保護していることを確認してください。

API は JWT の署名、発行者、アプリケーション、期限、本人のメールアドレスを検証します。

メールアドレスのリクエストヘッダーだけでは認証できない設計です。

下書きは検証済み本人の識別子のハッシュ、ブランチ名、ページ ID で分離します。API は既知の 10 ページだけを受け付け、URL と文書のページが一致しない場合は拒否します。データベースには編集文書と不透明な識別子だけを保存します。

保存時は本文のサイズと文書のバージョン・全項目をサーバーでも検証します。D1 の条件付き単一 SQL 文で更新するため、同じリビジョンからの保存が重なると片方だけが成功します。GET と PUT のレスポンスはキャッシュしません。公開版への取り込みは引き続き以下の別手順です。

## ブランチへ取り込む

```sh
pnpm editor:import /path/to/clasteria-home-draft.json
pnpm lint
pnpm test
NUXT_VISUAL_EDITOR=true pnpm generate
```

この既存コマンドによる取り込みは Home 専用で、`app/utils/homePage.json` のみを更新します。他ページの JSON は担当者が内容と差分を確認し、ページの初期デザインに反映します。記事の Markdown も別途内容確認が必要です。Git の差分とプレビューを確認し、承認されたブランチへコミット・プッシュしてください。本番へのマージや公開は別の承認が必要です。ブラウザーから Git や本番へ書き込む機能はありません。

## 安全性とライセンス

- バージョン付きのページ文書を検証し、既知のセクション・項目・画像・リンクだけを受け付けます。100 KB を超える文書や不正な色、重複 ID は拒否します。
- HTML、任意の CSS、JavaScript、埋め込み、画像アップロードは提供しません。文章は Vue の文字列として表示します。
- GrapesJS の標準プロジェクト JSON は読み込みません。検証済みのページ文書を専用コンポーネントへ変換します。テレメトリーは無効です。
- GrapesJS は BSD-3-Clause ライセンスです。依存パッケージのライセンスと `THIRD_PARTY_NOTICES.md` を参照してください。

## 検証

ユニットテストは `pnpm test` で実行します。ブラウザーを利用できる環境では、上記の静的生成後に `pnpm preview` を起動し、次のコマンドで編集フローを確認します。

```sh
BASE_URL=http://localhost:3000 CHROMIUM_PATH=/usr/bin/chromium pnpm exec node e2e-tests/editor.mjs
```

クラウド実装環境では Chromium のソケット作成が制限されています。この環境の自動テストだけでは、実際の Cloudflare バインディングや別の PC からの保存は確認できません。テストスクリプトには編集・並べ替え・履歴・保存と復元・入出力・不正な URL・プレビューと公開版の分離・リセット・モバイル幅の確認を含めています。

サーバー API のテストでは、実際の SQLite に対する保存・読み込み・同時更新の競合・本人とブランチの分離を確認します。認証テストは署名付き JWT で期限・発行者・アプリケーション・本人の検証を確認します。生成済み Worker とメンテナンス用リダイレクトの統合もテストします。

- [Cloudflare Pages D1 バインディング](https://developers.cloudflare.com/pages/functions/bindings/)
- [Cloudflare Access JWT 検証](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/validating-json/)


非公開ページの編集画面は `/editor?page=onigokko` のように開きます。公開側の `/onigokko` などは引き続きメンテナンス先へ移動します。
エディター保存やプレビューから公開状態を変更する経路はありません。
編集画面と下書きプレビューの登録画像は、既存の原寸素材を直接読み込みます。公開ページの静的生成では発見できない未公開ページ用素材も表示できます。公開ページの画像最適化は維持します。

複数ページのブラウザーチェックは、同じ環境で次のスクリプトを実行します。

```sh
BASE_URL=http://localhost:3000 CHROMIUM_PATH=/usr/bin/chromium pnpm exec node e2e-tests/editor-pages.mjs
```
