# Home ビジュアルエディター

Home の既存 Vue コンポーネントを GrapesJS OSS core で編集します。新しいアカウントや外部 CMS は不要です。

## 開く

- ブランチプレビューで Home 右下の「Home を編集」を選ぶか、`/editor` を開きます。既存の Cloudflare Access の認証が適用されます。
- `pnpm dev` でも利用できます。静的生成をローカルで試す場合は `NUXT_VISUAL_EDITOR=true pnpm generate` を実行します。
- Cloudflare Pages の `main` ブランチではエディターを生成しません。通常の本番ビルドでも明示的に有効化しない限り生成しません。エディターの URL は検索対象から除外します。

## 編集できる内容

- Home のメインビジュアル、紹介、ニュース、お問い合わせを選択して編集できます。
- 紹介・ニュース・お問い合わせは追加、複製、削除できます。最大 12 セクションです。メインビジュアルは 1 個を維持します。
- キャンバスやレイヤーで並べ替えられます。「上へ」「下へ」でも操作できます。
- 文章、登録済みの画像、公開済みのリンク、アクセント色、背景色、上下の余白を変更できます。
- 「元に戻す」「やり直す」、PC・スマートフォン幅での表示確認ができます。履歴は編集画面を開いている間のみ保持します。
- ニュースの記事は既存の公開条件で取得します。記事本文、ヘッダー、フッター、未公開ゲームや会員機能は編集対象に含めません。

## 保存とプレビュー

「下書きを保存」を押すと、Cloudflare D1 に保存します。同じ Pixelsia アカウントで同じブランチの編集画面を開けば、別の PC から読み込めます。サーバー保存は公開操作ではありません。公開ページは下書きを読み込みません。

編集内容は端末・ブラウザーにも自動バックアップします。サーバーへの未保存表示と、端末のバックアップ表示は別です。保存先が未設定の場合や通信・認証に失敗した場合は、その旨を表示します。サーバー保存に成功したとは表示しません。

初めての端末ではサーバーの下書きを読み込みます。端末の下書きがある場合は勝手に置き換えません。「サーバーの下書きを読み込む」で確認してから読み込めます。別の端末で更新されていた場合は保存を拒否します。必要な変更を JSON に書き出してから最新版を読み込み、変更を反映してください。

「下書き書き出し」で JSON を保管してください。別の端末や別のプレビュー URL では「下書き読み込み」で復元できます。読み込みは現在の下書きと編集履歴を置き換えるため、必要な変更は先に書き出してください。「公開版にリセット」は確認してから実行します。

読み取れない端末の下書きは、自動で上書きせずに保護します。「元のバックアップを書き出す」で元データを保管できます。復旧用保存枠が使用済みの場合や容量不足の場合は端末への上書きを止めます。その場合は、元データと現在の下書きを両方書き出してください。

「プレビュー」は同じ Vue コンポーネントと公開済み記事を使用します。移動先は実際のサイトなので、リンクを開くと公開版に移ります。プレビューの表示だけで公開はされません。機密情報は入力しないでください。共有端末では下書きが残ります。

## サーバー保存の設定

設定は Cloudflare の既存 Pages プロジェクトの Preview 環境だけに適用します。新しい資格情報や公開用 CMS は不要です。本番環境にデータベースをバインドしないでください。

1. 承認後に、専用 D1 データベース `clasteria-editor-drafts-preview` を作成します。有料プランへ変更しません。
2. そのデータベースに `migrations/0001_editor_drafts.sql` を適用します。公開データは書き換えません。
3. Pages の Preview 環境に D1 バインディング `CLASTERIA_DRAFTS` を追加します。
4. Preview のランタイム変数に、次の値を設定します。
   - `CLASTERIA_ACCESS_ISSUER`: 既存 Access チームの `https://<team>.cloudflareaccess.com`。末尾のスラッシュは付けません。
   - `CLASTERIA_ACCESS_AUD`: 既存プレビュー用 Access アプリケーションの Audience (AUD) Tag。
   - `CLASTERIA_EDITOR_ALLOWED_EMAILS`: 保存・読み込みを許可するメールアドレスのカンマ区切り一覧。初期設定は承認された本人のアカウントだけです。
5. 同じブランチを再デプロイし、認証済みの独立した 2 セッションで保存・読み込みを確認します。

これらの値はサーバーだけで読み取ります。Nuxt の公開ランタイム設定やリポジトリーにトークン・秘密情報を置かないでください。Access の既存ポリシーを緩める必要はありません。Access アプリケーションが編集画面と `/api/editor/*` の両方を保護していることを確認してください。

API は JWT の署名、発行者、アプリケーション、期限、本人のメールアドレスを検証します。

メールアドレスのリクエストヘッダーだけでは認証できない設計です。

下書きは検証済み本人の識別子のハッシュとブランチ名で分離します。データベースには編集文書と不透明な識別子だけを保存します。

保存時は本文のサイズと文書のバージョン・全項目をサーバーでも検証します。D1 の条件付き単一 SQL 文で更新するため、同じリビジョンからの保存が重なると片方だけが成功します。GET と PUT のレスポンスはキャッシュしません。公開版への取り込みは引き続き以下の別手順です。

## ブランチへ取り込む

```sh
pnpm editor:import /path/to/clasteria-home-draft.json
pnpm lint
pnpm test
NUXT_VISUAL_EDITOR=true pnpm generate
```

取り込みは `app/utils/homePage.json` のみを更新します。Git の差分とプレビューを確認し、承認されたブランチへコミット・プッシュしてください。本番へのマージや公開は別の承認が必要です。ブラウザーから Git や本番へ書き込む機能はありません。

## 安全性とライセンス

- バージョン付きの Home 文書を検証し、既知のセクション・項目・画像・リンクだけを受け付けます。100 KB を超える文書や不正な色、重複 ID は拒否します。
- HTML、任意の CSS、JavaScript、埋め込み、画像アップロードは提供しません。文章は Vue の文字列として表示します。
- GrapesJS の標準プロジェクト JSON は読み込みません。検証済みの Home 文書を専用コンポーネントへ変換します。テレメトリーは無効です。
- GrapesJS は BSD-3-Clause ライセンスです。依存パッケージのライセンスと `THIRD_PARTY_NOTICES.md` を参照してください。

## 検証

ユニットテストは `pnpm test` で実行します。ブラウザーを利用できる環境では、上記の静的生成後に `pnpm preview` を起動し、次のコマンドで編集フローを確認します。

```sh
BASE_URL=http://localhost:3000 CHROMIUM_PATH=/usr/bin/chromium pnpm exec node e2e-tests/editor.mjs
```

クラウド実装環境では Chromium のソケット作成が制限されています。この環境の自動テストだけでは、実際の Cloudflare バインディングや別の PC からの保存は確認できません。テストスクリプトには編集・並べ替え・履歴・保存と復元・入出力・不正な URL・プレビューと公開版の分離・リセット・モバイル幅の確認を含めています。

サーバー API のテストでは、実際の SQLite に対する保存・読み込み・同時更新の競合・本人とブランチの分離を確認します。認証テストは署名付き JWT で期限・発行者・アプリケーション・本人の検証を確認します。生成済み Worker とメンテナンス用リダイレクトの統合もテストします。

- [Cloudflare Pages D1 バインディング](https://developers.cloudflare.com/pages/functions/bindings/)
- [Cloudflare Access JWT 検証](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/validating-json/)
